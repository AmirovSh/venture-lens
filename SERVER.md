# Venture Lens на VPS

Проверено 18 ноября 2026 года. VPS `91.108.213.165`: Ubuntu 24.04, 4 vCPU, 8 ГБ RAM, 60 ГБ NVMe. Сервис работает в K3s, namespace `venture-lens-demo`. Публичный сайт с авторизацией и HTTPS доступен на бесплатном поддомене DuckDNS. Подробности — в PUBLIC_DEMO.md.

## Доступ

- Приватный административный доступ к приложению через SSH: **http://127.0.0.1:3210**.
- Публичный сайт доступен с других устройств без SSH. Argo CD и административный адрес 127.0.0.1 остаются доступны через SSH.

Для административного SSH-туннеля после перезапуска компьютера:

```powershell
.\.venv\Scripts\python.exe platform\start_demo.py
```








Повторное внесение явно разрешённых реквизитов/ротация:

```powershell
# Затем: k3s kubectl -n venture-lens-demo rollout restart deployment/corporate-llm
```

Скрипт передаёт Secret через SSH stdin и не сохраняет расшифрованный локальный ключ. Профиль и пароль остаются также в исходной пользовательской папке. Дамп исследований не содержит Kubernetes Secrets: при восстановлении всего VPS их нужно внести отдельно из защищённого источника. Образ адаптера добавлен в подготовленную сборку/публикацию GitHub Actions; сами облачные Actions ещё не запускались.

## Платформа

| Компонент | Конфигурация демо |
| --- | --- |
| Next.js web | 1 реплика |
| FastAPI API | HPA, 1–2 реплики по CPU |
| Python worker | KEDA, 1–2 реплики по готовой очереди PostgreSQL |
| PostgreSQL 17.12 | 1 StatefulSet, постоянный том |
| SeaweedFS S3 4.54 | 1 StatefulSet, постоянный том; источники по SHA256 |
| SearXNG | 1 реплика, image закреплён digest, внутренняя сеть |
| Demo access | 2 реплики, общие PostgreSQL-сессии/лимиты, owner/viewer |
| Public edge | Caddy 2.11.9, HTTPS на DuckDNS-домене, постоянное хранилище сертификатов |
| K3s | v1.37.2+k3s1, systemd, шифрование Secrets включено |
| Argo CD / KEDA | v3.6.1 / v2.21.1 |

Девять логических компонентов — web, API, worker, PostgreSQL, S3, поиск, corporate-llm, demo-access и public-edge — имеют отдельные контейнеры. Дополнительно работают контроллеры платформы. Это **один физический домен отказа**: отказ VPS/диска остановит всё размещённое на нём. Реплики на одном сервере не обеспечивают HA хоста.

API и worker используют общие лимиты провайдеров в PostgreSQL. Увеличение числа worker не отменяет квоты LLM и поиска. Ошибки зависимостей переводят работу в ожидание с повторами; потерянный worker освобождается через lease и fencing. Probes и Kubernetes пересоздают контейнеры. Argo CD восстанавливает объявленную конфигурацию из Git. При дефектном образе нужен возврат к проверенному релизу; автоматической генерации исправлений кода нет.

## GitOps и CI/CD


GitHub Actions с проверками, fault-тестами, публикацией проверенных образов в GHCR и продвижением digest подготовлены в `.github/workflows`. **GitHub-репозиторий ещё не подключён, облачные Actions не запускались.** Для автоматических релизов нужно подключить репозиторий/registry, защиту ветки и переключить источник Argo CD. Production overlay содержит обязательные placeholders и не используется как готовая конфигурация.

Bootstrap: `platform/server/bootstrap.sh` → `build.sh` → `deploy.py` → `addons.py`. До запуска нужны проверенный SSH-ключ, исходники `/opt/venture-lens/source`, приватный `runtime.json` и Secret настроек SearXNG. Для публичного доступа после миграции API также нужен `platform/configure_public_demo.py`: он создаёт ограниченную роль БД и Secret авторизации. Пока авторизация не готова, публичный шлюз не пропускает запросы к приложению. `addons.py` использует официальные manifests версий из `platform/toolchain.json`, сохранённые на VPS как `keda-install.yaml` и `argocd-install.yaml`. Секреты исключены из Git bundle и Docker context.

## Резервное копирование

Создать новую копию, скачать на компьютер, проверить SHA256 и пробное восстановление:

```powershell
.\.venv\Scripts\python.exe platform\backup_demo.py --verify-restore
```

`pg_dump` создаёт согласованный дамп; неизменяемые источники копируются после него. Кеш для восстановления не нужен. Копия на самом VPS не защищает от потери VPS; внехостовая копия — скачанная папка на компьютере. **Регулярное внешнее расписание пока не включено.** Production CronJob для отдельного backup S3 подготовлен; доступ к хранилищу ещё не задан. Гарантированного RPO/PITR на демо нет.

При аварии восстановить дамп в новую пустую БД, источники в новый bucket, проверить manifest/SHA256, записи и заметки, затем переключить подключения. Скрипт пробного восстановления не меняет подключение рабочего приложения.

## Администрирование


Снаружи разрешены SSH 22/tcp и публичный HTTPS/HTTP-redirect на 443/80. Kubernetes API закрыт firewall. Все запросы к публичному приложению проходят через авторизацию; web/Argo port-forward по-прежнему слушают только loopback. Подробности — в PUBLIC_DEMO.md.

Проверка через существующий маршрут:

```powershell
@'
k3s kubectl -n venture-lens-demo get pods,hpa,scaledobject
k3s kubectl -n argocd get application venture-lens
systemctl is-active k3s venture-lens-web-forward venture-lens-argo-forward
'@ | .\.venv\Scripts\python.exe platform\ssh_client.py
```

`venture-lens-web-forward`, `venture-lens-argo-forward`, `venture-lens-git` включены в systemd, имеют `Restart=always` и следуют перезапуску K3s. Для доступа без этого компьютера нужен собственный безопасный SSH-маршрут и защищённая копия ключа.

Для длительного использования остаются сервисные VPN/mTLS-реквизиты с ротацией, GitHub/registry, пользовательские кабинеты/OIDC, внешние регулярные backups и мониторинг с уведомлениями. Для устойчивости к отказу хоста нужны несколько узлов и внешние/HA сервисы данных. Нагрузочная ёмкость этого VPS пока не измерялась.

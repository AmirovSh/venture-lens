# Venture Lens на VPS

[Демонстрационный сайт](https://venture-lens.duckdns.org) работает на одном VPS под K3s. Публичный трафик идёт через HTTPS и шлюз аутентификации. Новые исследования используют отдельный сервер моделей с общими лимитами. Сайт, вход и сохранённые исследования доступны независимо от выполнения новых запросов к моделям.

Текущий релиз и результат GitHub Actions описаны в [DELIVERY.md](DELIVERY.md). Argo CD синхронизирует `deploy/overlays/demo` из `master`. Для обновления приложения в Git закрепляются digest проверенных образов, затем проверяются готовность Kubernetes, статус `Synced / Healthy` и сценарии на публичном сайте.

## Компоненты демонстрации

| Компонент | Конфигурация |
| --- | --- |
| Next.js | 1 реплика |
| FastAPI | HPA, 1–2 реплики по CPU |
| Worker | KEDA, 1–2 реплики по готовой очереди PostgreSQL |
| PostgreSQL и S3 | Независимые StatefulSet, постоянные тома |
| SearXNG | 1 реплика во внутренней сети |
| Вход | 2 реплики, общие сессии и лимиты в PostgreSQL |
| Публичный HTTPS | Caddy, постоянное хранилище TLS |
| Управление инфраструктурой | K3s, Argo CD и KEDA |

API и worker получают системный адрес `LLM_BASE_URL` и реквизиты подключения из внешнего Kubernetes Secret `venture-lens-runtime`. Оператор задаёт Secret до синхронизации и обновляет pod после изменения значений среды. Администратор может отдельно проверить сервер моделей и настроить модели и промпты по ролям. Подробности в [PRODUCT_CONTROLS.md](PRODUCT_CONTROLS.md) и [CONNECTION_ROTATION.md](CONNECTION_ROTATION.md).

Проверки готовности и контроллеры Kubernetes восстанавливают контейнеры. Worker использует lease и fencing, а API и worker делят лимиты в PostgreSQL. Argo CD восстанавливает конфигурацию из Git. Отказ одного VPS остановит все размещённые на нём компоненты. Реплики на одном узле не обеспечивают доступность при потере хоста.

## Резервное копирование и восстановление

Создайте согласованный дамп PostgreSQL, сохраните неизменяемые снимки источников, проверьте контрольные суммы и вынесите копию за пределы VPS. Выполняйте пробное восстановление в отдельной БД и отдельном бакете. Проверьте исследования, заметки и доступность снимков перед переключением. При восстановлении перед открытием сайта отзовите сессии и ожидающие ссылки восстановления аккаунтов.

Пробное восстановление и масштабирование проверялись отдельно. Регулярный внешний график резервного копирования и мониторинг с уведомлениями остаются задачами эксплуатации. Сведения о проверках собраны в [VERIFICATION.md](VERIFICATION.md).

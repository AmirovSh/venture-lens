# Демонстрация Venture Lens

Адрес для показа с компьютера или телефона: **https://venture-lens.duckdns.org**. Бесплатный поддомен зарегистрирован в вашем аккаунте DuckDNS. SSH-туннель и включённый рабочий компьютер для сайта и LLM не нужны.

## Вход

| Учётная запись | Права | Локальный файл с паролем |
| --- | --- | --- |
| Новый аккаунт | Создание и управление только собственными исследованиями | Пароль задаётся при регистрации |

Для передачи проверяющему используйте ссылку и **только гостевой файл**. Учётные записи `owner` и `demo` используют общую демонстрационную область `main`. Личные исследования зарегистрированных пользователей им не видны.


## Регистрация и личное пространство

На странице входа есть ссылка «Создать аккаунт»: **https://venture-lens.duckdns.org/auth/register**. Требуются имя, уникальный логин (3–32 символа: латиница, цифры, `.`, `_`, `-`) и пароль длиной 12–128 символов с подтверждением. Логин регистронезависим. После регистрации пользователь автоматически входит в пустое личное пространство. Email не собирается; восстановление пароля и самостоятельное удаление аккаунта пока не реализованы — это указано в форме.

Роль `member` может создавать исследования, останавливать и повторять свои этапы, сохранять решения и экспортировать результаты. API проверяет принадлежность пространства во всех путях: список и карточки, события, аудит, экспорт, cancel/retry, решения моделей, снимки источников и метрики. Чужие ID возвращают 404. Владелец демонстрации не получает доступ к личным областям через интерфейс; администратор БД по-прежнему имеет технический доступ к данным.

Квоты: **одно активное исследование и три новых исследования за скользящие 24 часа**. Остановка не возвращает суточный слот; повтор продолжает прежнее исследование с прежним бюджетом. В интерфейсе показаны оставшиеся запуски и время освобождения слота. На PostgreSQL создание исследований сериализуется advisory lock, чтобы одновременные запросы не обходили квоты. Общий лимит активных исследований сервера и лимиты LLM сохраняются. Регистрация ограничена пятью попытками на IP в час и 200 аккаунтами на демонстрационном сервере.

Аккаунты и PBKDF2-хеши хранятся в PostgreSQL. Шлюз удаляет входящие `X-Venture-*` и добавляет подписанное HMAC утверждение о роли и пространстве со сроком 60 секунд. API требует корректную подпись, а права гостя проверяет повторно. Подписывающий ключ доступен только API и шлюзу через Kubernetes Secret. Прямой административный port-forward к web не заменяет вход через публичный HTTPS-шлюз.

Включение формы задаёт `REGISTRATION_ENABLED` в публичном ConfigMap. `false` закрывает создание аккаунтов, сохраняя вход существующих пользователей. При первом обновлении сначала применены миграция `0003_registration`, права БД и новый Secret, затем новые API/auth-реплики с закрытой регистрацией; форма открыта после проверки всех реплик. Не откатывайте API на версию без проверки пространств после появления личных аккаунтов.

## HTTPS и доступ

Caddy **2.11.9**, образ закреплён digest, автоматически выпускает и обновляет сертификат Let’s Encrypt для `venture-lens.duckdns.org`. DNS A-запись указывает на `91.108.213.165`. Токен DuckDNS на VPS не переносится: IP сервера постоянный, динамическое обновление не требуется. При смене IP нужно изменить запись в панели DuckDNS.

Старый адрес `https://91.108.213.165` перенаправляет на домен кодом 308 с сохранением пути и параметров. Для него сохранён отдельный IP-сертификат с ACME-профилем `shortlived`. Данные Caddy находятся на постоянном PVC. Порты 80/443 нужны также для продления сертификатов. HTTP перенаправляется на HTTPS. При переходе с IP на домен потребуется снова войти: cookie привязан к имени сайта, пароли прежние.

`Интернет → Caddy:443 → demo-access:8090 → web:3100 → API:8100`.

Авторизация имеет две реплики. Сессии хранятся в PostgreSQL в виде SHA256 от случайного токена, срок — 8 часов. Cookie имеет Secure/HttpOnly/SameSite=Lax. Выход удаляет сессию в БД, старый cookie больше не работает. Пароли хранятся только как PBKDF2-SHA256 (600 000 итераций). Роль гостя проверяется сервером для каждого запроса, отключение кнопок в интерфейсе не является единственной защитой.

Изменяющие запросы требуют правильного Origin. Лимит входа — 10 попыток на IP за 5 минут, общий в PostgreSQL для всех реплик. Caddy перезаписывает X-Forwarded-For, а NetworkPolicy допускает к шлюзу только Caddy. Роль БД `venturelens_access` имеет права только на таблицы сессий и лимитов, а также SELECT/INSERT на `registered_users`, без доступа к исследованиям. При ошибке БД доступ закрывается с 503.

При перекате авторизации старый pod ждёт 5 секунд перед остановкой; Caddy повторяет безопасные GET/HEAD/OPTIONS при ошибках соединения. Отправленные POST/PATCH автоматически не повторяются. Сессии сохранились после реального переката двух реплик во внешнем HTTPS-тесте.


## Управление

Единый публичный адрес задан в `deploy/components/public-demo/kustomization.yaml`: `PUBLIC_ORIGIN` и `ALLOWED_ORIGINS`. Изменение через GitOps обновляет Caddy, авторизацию и API; пересборка образов не требуется. Затем нужно повторно запустить настройку доступа, чтобы обновить URL в локальных файлах.

Повторная настройка существующих реквизитов, без смены паролей владельца/гостя и сессий:

```powershell
.\.venv\Scripts\python.exe platform\configure_public_demo.py
```

Для смены обоих паролей выполнить ту же команду с `--rotate`, затем перезапустить `deployment/demo-access`. После обновления экземпляров старые сессии не пройдут проверку версии пароля. Новые пароли появляются только в локальных файлах доступа.

Внешняя проверка HTTPS, ролей, экспорта, выхода и сохранения сессий при перекате:

```powershell
.\.venv\Scripts\python.exe platform\verify_public_demo.py --restart-auth --registration
```

Эти административные команды используют прежний SSH/SOCKS-маршрут данного компьютера. Проверяющему для браузера он не нужен. Тест не создаёт платных исследований и не печатает пароли/cookie. Опция `--registration` создаёт два QA-аккаунта, проверяет их изоляцию, повторный вход и квоты; их реквизиты сохраняются только в игнорируемом `.platform/registration-check-accounts.json`.

## Проверки и восстановление

- 59 автоматических тестов пройдены в отдельном PostgreSQL-контейнере без пропусков, включая конкурентный запуск запросов. На локальном SQLite: 57 пройдены, две PostgreSQL-проверки пропущены.
- В браузере проверены оба входа, гостевые ограничения, форма создания у владельца, мобильная рабочая область и меню при ширине 390 px. После перехода на DuckDNS в браузере повторно проверены вход гостя, загрузка настоящего исследования и отключённые кнопки изменения; внешние проверки обоих входов и сохранения сессий при перекате также пройдены.
- Перед миграцией регистрации и после неё сохранены серверные копии `/opt/venture-lens/backups/20261118T103031Z` и `20261118T104637Z`. Их скачивание не выполнялось: автоматическая проверка отклонила передачу полной БД и источников.
- Историческая резервная копия после миграции `0002_demo_access` скачана вне VPS, восстановлена в отдельную временную БД: 2 исследования, 20 карточек, 82 вызова, 535 проверенных объектов источников. Рабочая БД не очищалась.


При восстановлении всего VPS отдельно внести Kubernetes Secrets, восстановить БД/источники, повторно выдать ограниченные права роли сессий. **В новой восстановленной БД удалить строки `demo_sessions` перед открытием сайта**, чтобы резервная копия не вернула уже отозванные сессии. Сертификат Caddy хранится отдельно на PVC; при его потере потребуется новый выпуск ACME. Внешнее регулярное расписание backups и мониторинг продления/доступности пока не настроены.

Это демо на одном VPS с одним HTTPS-входом, а не HA по физическим узлам. Восстановление пароля, управление аккаунтами, OIDC и нагрузочное тестирование остаются отдельными задачами. Для собственного домена нужно направить DNS на VPS и изменить `PUBLIC_ORIGIN`/`ALLOWED_ORIGINS` в единой конфигурации через GitOps.

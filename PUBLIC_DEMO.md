# Демонстрация Venture Lens

Адрес для показа с компьютера или телефона: **https://venture-lens.duckdns.org**. Бесплатный поддомен зарегистрирован в вашем аккаунте DuckDNS. SSH-туннель и включённый рабочий компьютер для сайта и LLM не нужны.

## Вход

| Учётная запись | Права | Локальный файл с паролем |
| --- | --- | --- |

Для передачи проверяющему используйте ссылку и **только гостевой файл**. Это одна общая демонстрационная рабочая область: гостю видны все исследования стенда. Персональных кабинетов и изоляции исследований по пользователям здесь нет.


## Сценарий показа

2. Показать результат: 10 карточек, 42 LLM-вызова, одна прошла автоматические условия, девять требуют проверки. Объяснить, что индекс не является вероятностью успеха.
3. Открыть карточку, паспорта доказательств, независимую критику и план проверки.
4. Выбрать две карточки для сравнения, открыть библиотеку источников и журнал.

## HTTPS и доступ

Caddy **2.11.9**, образ закреплён digest, автоматически выпускает и обновляет сертификат Let’s Encrypt для `venture-lens.duckdns.org`. DNS A-запись указывает на `91.108.213.165`. Токен DuckDNS на VPS не переносится: IP сервера постоянный, динамическое обновление не требуется. При смене IP нужно изменить запись в панели DuckDNS.

Старый адрес `https://91.108.213.165` перенаправляет на домен кодом 308 с сохранением пути и параметров. Для него сохранён отдельный IP-сертификат с ACME-профилем `shortlived`. Данные Caddy находятся на постоянном PVC. Порты 80/443 нужны также для продления сертификатов. HTTP перенаправляется на HTTPS. При переходе с IP на домен потребуется снова войти: cookie привязан к имени сайта, пароли прежние.

`Интернет → Caddy:443 → demo-access:8090 → web:3100 → API:8100`.

Авторизация имеет две реплики. Сессии хранятся в PostgreSQL в виде SHA256 от случайного токена, срок — 8 часов. Cookie имеет Secure/HttpOnly/SameSite=Lax. Выход удаляет сессию в БД, старый cookie больше не работает. Пароли хранятся только как PBKDF2-SHA256 (600 000 итераций). Роль гостя проверяется сервером для каждого запроса, отключение кнопок в интерфейсе не является единственной защитой.

Изменяющие запросы требуют правильного Origin. Лимит входа — 10 попыток на IP за 5 минут, общий в PostgreSQL для всех реплик. Caddy перезаписывает X-Forwarded-For, а NetworkPolicy допускает к шлюзу только Caddy. Роль БД `venturelens_access` имеет права только на таблицы сессий и лимитов, без доступа к исследованиям. При ошибке БД доступ закрывается с 503.

При перекате авторизации старый pod ждёт 5 секунд перед остановкой; Caddy повторяет безопасные GET/HEAD/OPTIONS при ошибках соединения. Отправленные POST/PATCH автоматически не повторяются. Сессии сохранились после реального переката двух реплик во внешнем HTTPS-тесте.


## Управление

Единый публичный адрес задан в `deploy/components/public-demo/kustomization.yaml`: `PUBLIC_ORIGIN` и `ALLOWED_ORIGINS`. Изменение через GitOps обновляет Caddy, авторизацию и API; пересборка образов не требуется. Затем нужно повторно запустить настройку доступа, чтобы обновить URL в локальных файлах.

Повторная настройка существующих реквизитов, без смены паролей и сессий:

```powershell
.\.venv\Scripts\python.exe platform\configure_public_demo.py
```

Для смены обоих паролей выполнить ту же команду с `--rotate`, затем перезапустить `deployment/demo-access`. После обновления экземпляров старые сессии не пройдут проверку версии пароля. Новые пароли появляются только в локальных файлах доступа.

Внешняя проверка HTTPS, ролей, экспорта, выхода и сохранения сессий при перекате:

```powershell
.\.venv\Scripts\python.exe platform\verify_public_demo.py --restart-auth
```

Эти административные команды используют прежний SSH/SOCKS-маршрут данного компьютера. Проверяющему для браузера он не нужен. Тест не создаёт платных исследований и не печатает пароли/cookie.

## Проверки и восстановление

- 46 автоматических тестов пройдены, один PostgreSQL-only тест локально пропущен. Реальные PostgreSQL-сессии, роль БД и proxy/API проверены отдельно на VPS.
- В браузере проверены оба входа, гостевые ограничения, форма создания у владельца, мобильная рабочая область и меню при ширине 390 px. После перехода на DuckDNS в браузере повторно проверены вход гостя, загрузка настоящего исследования и отключённые кнопки изменения; внешние проверки обоих входов и сохранения сессий при перекате также пройдены.
- Резервная копия после миграции `0002_demo_access` скачана вне VPS, восстановлена в отдельную временную БД: 2 исследования, 20 карточек, 82 вызова, 535 проверенных объектов источников. Рабочая БД не очищалась.


При восстановлении всего VPS отдельно внести Kubernetes Secrets, восстановить БД/источники, повторно выдать ограниченные права роли сессий. **В новой восстановленной БД удалить строки `demo_sessions` перед открытием сайта**, чтобы резервная копия не вернула уже отозванные сессии. Сертификат Caddy хранится отдельно на PVC; при его потере потребуется новый выпуск ACME. Внешнее регулярное расписание backups и мониторинг продления/доступности пока не настроены.

Это демо на одном VPS с одним HTTPS-входом, а не HA по физическим узлам. Полноценные пользовательские кабинеты, OIDC и нагрузочное тестирование остаются отдельными задачами. Для собственного домена нужно направить DNS на VPS и изменить `PUBLIC_ORIGIN`/`ALLOWED_ORIGINS` в единой конфигурации через GitOps.

# Пять архитектурных решений

1. **Модульный монолит и отдельный worker.** Next.js отвечает за UX, FastAPI — за контракты, worker — за длительную работу. PostgreSQL хранит результаты и очередь. Отброшены микросервисы, Kafka и Kubernetes: для 10–15 моделей они усложняют эксплуатацию. Temporal имеет смысл при многодневных процессах и человеческих согласованиях.

2. **Карточка и доказательства — основной контракт.** Все модели получают одинаковую структуру, индекс рассчитывается кодом. Веса: 30% доступ к покупателям, 25% путь к оплате, 20% MVP, 15% бюджет, 10% зависимости. Это исходная гипотеза под цель «первая оплата за 90 дней», а не обученная вероятность. Неизвестное образует диапазон; существенный подтверждённый риск уменьшает индекс по конфигу.


4. **Совместимый LLM-клиент вместо тяжёлой агентной среды.** Для этого шлюза реализован небольшой адаптер с Pydantic-валидацией и JSON Schema на границе. Windows Schannel обеспечивает mTLS без экспорта ключа. Это осознанное упрощение исходного предложения PydanticAI. Входы, модель, usage и ошибки сохраняются. Qwen проверена для структурированных ответов, DeepSeek используется для критики. При сбое этап повторяем ограниченно; резервная модель включается только конфигурацией и отражается в аудите.

5. **Доказательная неопределённость важнее заполненной таблицы.** Источники реально загружаются; совпадение цитаты проверяет сервер. Неполная страница, недоказанная оценка компании и юридическая неопределённость ведут к review. Противоречивые источники сохраняются. Публичный RSS-поиск оказался нерелевантным при проверке; локальная конфигурация переключена на существующий SearXNG. Доступны адаптеры Exa и публичного поиска, но их качество нельзя считать одинаковым.
